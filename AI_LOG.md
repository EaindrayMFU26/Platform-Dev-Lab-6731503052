## 4. Decisions the AI made

These were the AI's choices, not requirements of the brief. Each one is explained in
`API_CONTRACT.md` ("Required behaviour and optional choices", "Assumptions") or `SCHEMA.md`.

- An unknown `equipmentId` returns 404 rather than 400.
- A booking may start exactly when another ends (the end time is exclusive).
- Date-times must include a time zone and are stored and returned in UTC.
- Bookings in the past are allowed; there is no minimum or maximum length.
- All five fields are required on create; text is trimmed; limits of 64, 100 and 500 characters.
- Booking ids are random UUIDs; unknown properties in a request body are ignored.
- The overlap check and the write are one SQL statement instead of a check followed by an insert.
- Times are stored as text with a `CHECK` on the format, not as numbers.
- The overlap rule is not also enforced by database triggers.
- CORS allows every origin.
- The names of the Worker (`equipment-booking-api`) and of the D1 database
  (`equipment-booking-db`). Cloudflare placed the database in its APAC region automatically.

## 5. Problems the AI found while building, and how they were fixed

These are findings from the AI's own testing between 14:28 and 14:55, before it had seen the
Quality Gate. The review against the Quality Gate that followed (prompt 3) is in
`QUALITY_GATE_REVIEW.md`. That review was run by the AI as well; the student's own part of it is
still open.

| # | What was found | How it was fixed | Evidence |
|--:|---|---|---|
| 1 | The first schema checked the time format with a `GLOB` pattern of about 110 bytes. The table was created without complaint, but D1 rejects LIKE/GLOB patterns longer than 50 bytes when they run, so every `POST /bookings` returned 500. The first test run failed 15 of 32 cases. | The `CHECK` now compares the value with SQLite's own rendering of it (`strftime`). This is shorter and stricter: it also rejects impossible dates. | All 32 cases pass. `SCHEMA.md`, "Database constraints, tested directly". Limit confirmed locally: a 50-byte pattern runs, a 51-byte pattern fails. |
| 2 | JavaScript accepts impossible dates: `new Date('2026-02-30T09:00:00.000Z')` becomes 2 March, so a booking would silently land on the wrong day. | `parseDateTime()` requires the value to survive a round trip unchanged. | Case 9 in `TEST_EVIDENCE.md`. |
| 3 | SQLite's `strftime` returns `24:00` unchanged, so the replacement `CHECK` from row 1 would have accepted it. | Added the `'+0 seconds'` modifier, which makes SQLite recalculate the date. Checked that every millisecond value, every second of a day and every day from 2000 to 2099 still passes. | `SCHEMA.md`: a direct SQL write with `24:00` is rejected. |
| 4 | The first race-condition test (five curl processes started together) could not detect a race. It still passed when the code was temporarily replaced by a deliberately naive "check, then insert", because separate processes start too far apart to collide. | Case 23 now sends 20 requests at once from one process, 40 times. Under that load the naive version double-booked in 4 of 40 rounds (up to 17 bookings for one slot); the real code in 0 of 40. The naive version was a temporary edit and was reverted. | Case 23. `SCHEMA.md`, "Why one statement". |
| 5 | After the bug in row 1, some test cases "passed" by accident: they called `/bookings/undefined` and got the 404 they expected. | Cases that depend on an earlier booking now fail explicitly if it is missing, and case 22 also checks the error message. | `need()` in `tests/run-tests.mjs`. |
| 6 | CORS headers were only added under `/api/*`. With a wrong Base URL, a browser tester would have shown a CORS error instead of the real problem (404). | CORS is applied to every route. | `curl -i -H "Origin: http://localhost:5173" http://localhost:8787/bookings` returns a JSON 404 with `Access-Control-Allow-Origin: *`. |
| 7 | In Windows PowerShell 5.1, JSON typed inline after `curl.exe -d` loses its double quotes, so the API (correctly) answers 400. | Documented a form that works (pipe the JSON to `--data-binary "@-"`); the automated tests start curl directly and are not affected. | README, "Windows PowerShell". Both forms were run. |

Observed and left as it is: with 100 simultaneous requests, the local dev server's proxy dropped
connections in one round (500 responses produced by wrangler, "Network connection lost", not by
the API code). That is far beyond the load in the brief.
